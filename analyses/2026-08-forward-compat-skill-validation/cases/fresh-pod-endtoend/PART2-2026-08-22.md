## Real script defects caught by fresh-pod execution — 13 total

Every one would have blocked a fresh Claude session copying commands
from SKILL.md verbatim. Each was fixed on the spot and committed.

### resolve_versions.sh (2)

1. GITHUB_TOKEN required, but public https endpoints are anonymously
   readable on the dev cluster. Fix: try anonymous first.
2. Heredoc-vs-pipe stdin conflict — python got zero chars because
   the heredoc grabbed fd 0. Fix: pass via env var.

### setup_supported_env.sh (5)

3. No --index-url; pip default was CUDA torch (2GB). Fix: force
   .../whl/cpu.
4. PVC-autoload trap on the post-install sanity check. Fix: two-tier
   TORCH_DEVICE_BACKEND_AUTOLOAD=0 PYTHONNOUSERSITE=1 with fallback.
5. typing_extensions missing under --system-site-packages + NOUSERSITE.
   Fix: explicit pip install in prereqs.
6. SPYRE_COMMS_INSTALL_DIR not exported; only set by login shells.
   Fix: source /etc/profile.d/ibm-aiu-setup.sh in the script.
7. set -u tripped on _IBM_AIU_SETUP inside that profile file. Fix:
   set +u / set -u around the source.

### run_compat_smoke.sh (4)

8. Stage 1 hardcoded torch_spyre._inductor.decomp as required; module
   doesn't exist at 8aba5bc. Fix: required-vs-optional split.
9. Stage 1 asserted 'spyre' dynamo backend that doesn't exist.
   torch-spyre patches Inductor lowerings for tensors on the 'spyre'
   device. Fix: assert torch.spyre.device_count() >= 1 AND 'inductor'
   in list_backends().
10. Stage 2 used backend='spyre' — same conceptual error. Fix:
    backend='inductor' with .to('spyre'); switched dtype to fp16;
    rtol/atol=1e-3 (was 0.0).
11. Stage 3 checkout locator missed the skill's layout. Fix: also
    check $candidate/torch-spyre/tests/inductor.

### setup_latest_pytorch_env.sh (2)

12. set -u tripped on ibm-aiu-setup.sh (same as #7). Fix: same guard.
13. Nightly install skipped by "already satisfied" under
    --system-site-packages. Fix: --force-reinstall --no-deps.
